# Day 4 pre-registration: model exploration requested by the guide

Written and committed before any Day 4 run. Scope: the Task 1 and Task 2 candidate lists from the guide's model sheets, plus the metric set from the guide's metric sheet.

## Candidates
Task 1 (informative vs not informative):
- Text: TF-IDF+LR (existing), TF-IDF+Naive Bayes, TF-IDF+Random Forest, TF-IDF+Linear SVM, BiLSTM+GloVe Twitter 200d (fallback GloVe 6B 100d), BERTweet fine-tuned.
- Image (cached frozen features + head): ResNet50, DINOv2, CLIP image-only.
- Multimodal: calibrated late fusion (best text + best image), BERTweet (fine-tuned) + ResNet50 (frozen) concat + MLP, CLIP-feature fusion with a 2-class head.
Task 2 (8-class humanitarian):
- Text: TF-IDF+LR (class-weighted), Linear SVM, Naive Bayes, BERTweet with weighted CE.
- Multimodal: calibrated late fusion, BERTweet (fine-tuned) + ResNet50 (frozen) early fusion with weighted CE; BERTweet inside L4a cross-attention if time.
- Image heads and gated/cross-attention fusion: reused from D2 (§9.10), not rerun.
- Stretch only: ResNet50 fine-tuned, DeBERTa-v3 (bf16), ModernBERT, zero-shot VLM.

## Rules
1. **Task 1 label.** All Task 1 models (text, image, fusion) are trained and scored on the text informativeness label (`label_text`). The loader asserts this column.
2. **Splits and selection.** Same corrected splits, seeds 42/43/44. Select on dev (T1 headline weighted F1, T2 macro-F1). Test is scored once. Ties go to the simplest model.
3. **Deployed Task 1 model switch is decided on dev.** Switch from TF-IDF+LR to BERTweet only if the paired dev bootstrap CI (seed-averaged) of the gain excludes 0 AND the gain is positive at every seed. TF-IDF is deterministic, so each BERTweet seed is compared against it. Otherwise keep TF-IDF and justify on latency. Test is reported afterwards and not used to decide.
4. **Probabilities.** Every run saves dev and test probabilities. For the SVM, save `decision_function` scores; probability metrics use `CalibratedClassifierCV` fitted with CV on train (dev stays clean).
5. **Labelling.** The guide's model is reported as "BERTweet (fine-tuned) + ResNet50 (frozen)". Reason: frozen vs fine-tuned CLIP showed no difference (L3b); breadth was prioritised.
6. **Multiplicity.** Roughly 15-20 additional comparisons, no correction. Language stays "established / not distinguishable" (§9.10). Bootstrap CIs only for: best model vs the guide's core model, and fusion vs best unimodal.
7. **Metrics.** Task 1: accuracy, weighted F1 (headline), macro-F1, per-class P/R, MCC, ROC-AUC, confusion matrix. Task 2: macro-F1 (headline), weighted F1, accuracy, per-class P/R/F1, balanced accuracy, MCC, row-normalised 8x8 confusion matrix, top-2 accuracy. Top-2 is computed for more than 2 classes only. Both tasks: mean ± std over 3 seeds for trained neural models, fusion gain (multimodal minus best single modality, macro-F1 and headline), 10-15 error-analysis examples.
8. **BERTweet setup.** `use_fast=False`, `normalization=True`, max length 128, lr 2e-5, 4 epochs, select on dev. A sanity check must show `HTTPURL` and `@USER` in a tokenised example.
9. **Honesty.** Results from candidates added after seeing earlier Day 4 results are labelled post-hoc.
10. **Post-hoc arm (added after the first Day 4 results were seen).** BERTweet with plain unweighted cross-entropy, 3 seeds, everything else identical, to answer "why a weighted loss for Task 1 (71% informative / 29% not)?". Labelled post-hoc; it does not change the BERTweet headline arm (weighted), which was fixed before running.
11. **Task 2 provenance (pre-registered before any Task 2 Day 4 run).** Every Task 2 model initialises its text encoder from the hub (`vinai/bertweet-base`, `distilbert-base-uncased`, ...), never from a Task 1 checkpoint, head, logit file or fine-tuned weight, because T1 train contains 1,587 T2 test rows (D4_cross_task_overlap.json). Every Task 2 run JSON carries `task_name == "humanitarian"`, `label_col == "label_image"`, the T2 `train_split_sha256` and an `init_from` that is a hub id; `d4_prov.assert_init` (hub id only) is called by every Task 2 script before it builds a model, and `d4_prov.assert_run(run, "humanitarian")` by every script that consumes saved Task 2 runs. The mirror-image rule for Task 1 (rule 1 plus `assert_run(run, "informative")`) is enforced in `d4_t1_fusion.py`, `d4_t1_switch.py` and the loaders; the module-name guard in `d4_t1_data.data()` is kept as a secondary check.
12. **Provenance record.** Run JSONs carry `task` ("T1"/"T2", used in filenames) and `task_name` ("informative"/"humanitarian"). Task 1 runs made before `d4_prov.py` existed were back-filled with metadata only, with a parsed-JSON identity check (no pre-existing value changed), and every Task 1 run's stored `y_dev`/`y_test` was verified equal to the loader's labels (`D4_T1_audit.json`, 25/25).

## Deviations
- **Deployed Task 1 checkpoint is a retrain.** Original seed runs saved no weights; seed 42 was retrained with --save (dev wF1 0.8289 vs 0.8321 originally; 94.3% test-prediction agreement). Same-seed run-to-run variation (0.0032) exceeds the inter-seed dev spread (0.0030: 0.8321, 0.8292, 0.8300), so seed selection is within noise. Architecture claims use the 3-seed means; deployed-model numbers come from the bertweet_deploy run JSON (results/ablation/D4/T1_bertweet_deploy_seed42.json). No further seeds were retrained.

## Addendum: Task 2 BERTweet text-only arms (written before any Task 2 Day 4 run)
13. **Two BERTweet text-only arms, both 3 seeds (42/43/44), inverse-frequency weighted CE, 8 classes (`label_image`), select on dev macro-F1 with strict `>`, test scored once.**
    - **`bertweet_text_matched` (primary; the comparison with DistilBERT text-only, test macro-F1 0.294 ± 0.014).** Same recipe as that run (ablation/t2_train.py, `--variant text_only`, L4a config): 10 epochs, batch 32, AdamW weight decay 1e-4, encoder lr 1e-5 (0.1 x 1e-4) and head lr 1e-4, 3 linear warm-up epochs then cosine, grad clip 1.0, fp16 autocast, max length 128, head = Linear(768,256)+LayerNorm on the token states, first token, MLP(256,256,8) with dropout 0.2. **Differences from the DistilBERT run, all unavoidable or by design:** the encoder (BERTweet-base 135M vs DistilBERT 66M), its tokenizer, and the input text: BERTweet reads the raw `tweet_text` with its own normalisation (@USER, HTTPURL, demojised emoji) instead of `clean_tweet` output, which would remove the URLs BERTweet's normaliser expects.
    - **`bertweet_text_rule8` (rule 8's recipe, run as the pre-registered BERTweet setup).** 4 epochs, one lr 2e-5 for all parameters, 6% linear warm-up then linear decay (the Task 1 BERTweet recipe), otherwise as above. Not matched to the DistilBERT run (fewer epochs, different lr and schedule); reported alongside, not as the comparison.
    - **Why two:** rule 8 (lr 2e-5, 4 epochs) and the request to compare under the DistilBERT recipe (10 epochs) conflict. Neither arm is picked by test; the primary for the DistilBERT comparison is `bertweet_text_matched`, and the arm used downstream (late fusion, rule 5d) is the one with the higher mean dev macro-F1 (tie to the simpler, `rule8`).
    - Initialisation from the hub id `vinai/bertweet-base` only (rule 11); `d4_prov.assert_init` is called before the model is built.

## Addendum: Task 2 fusion, 5(c) and 5(d) (written and committed before any Task 2 fusion run)
14. **Available checkpoints / predictions (checked before running).** L4a checkpoints for seeds 42, 43 and 44 all exist; so do the DistilBERT text-only (t2_text_only) and image-only CLIP B/32 (t2_image_only) checkpoints. Dev and test probabilities were re-inferred for all nine without retraining (`d4_t2_reinfer.py`); every one reproduces the stored test accuracy and macro-F1 exactly, so all three seeds are used for every comparison below. Image-only CLIP B/32 and L/14 heads (inverse-frequency arm) are also stored as run JSONs from `artifacts/ablation/imbalance/{b32,l14}_inv_seed*.npz` (the B/32 logits agree 100% with the checkpoint's test argmax).
15. **5(c) calibrated late fusion.** Text side = `bertweet_text_rule8` (the rule-13 pick), image side = the image-only head with the higher mean dev macro-F1 among {`t2_img_clip_b32_inv`, `t2_img_clip_l14_inv`}. Each model's dev log-probabilities are temperature-scaled on dev (one temperature per model and seed), the two probability vectors are averaged with equal weight, seeds paired by seed. No weight tuning.
16. **5(d) core model, "BERTweet (fine-tuned) + ResNet50 (frozen)", 8 classes.** Recipe = the DistilBERT/L4a-matched recipe: 10 epochs, batch 32, AdamW weight decay 1e-4, encoder lr 1e-5 (0.1 x 1e-4) and every non-encoder module lr 1e-4, 3 linear warm-up epochs then cosine (epoch-level), grad clip 1.0, fp16 autocast, inverse-frequency weighted CE, select on dev macro-F1 with strict `>`, seeds 42/43/44, max length 128. The text tower is BERTweet initialised from the hub id `vinai/bertweet-base` (rule 11), reading the raw `tweet_text` with BERTweet normalisation. Image features are the frozen ResNet50 cache `artifacts/ablation/d2_feats/resnet50` (2048-d, ImageNet-pretrained `microsoft/resnet-50`, never trained). Architecture = the `concat` variant of t2_models: img_proj = Linear(2048,256)+LayerNorm, txt_proj = Linear(768,256)+LayerNorm on the token states (first token), classifier = Dropout(0.2), Linear(512,256), ReLU, Dropout(0.2), Linear(256,8). Provenance asserts: `d4_prov.check_t2_cache` (cache row order equals the T2 split image_id order; encoder is a pretrained hub model and frozen), `assert_init` (hub id only).
17. **Pre-registered comparisons, decided on the dev paired bootstrap (seed-averaged, 10,000 resamples, seed 20241025, macro-F1 headline, weighted F1 secondary); test is reported afterwards and decides nothing.** (i) core model vs L4a (`t2_L4a`, re-inferred, seeds 42/43/44); (ii) core model vs the image-only CLIP B/32 head (`t2_img_clip_b32`, seeds 42/43/44). Labels: "better" / "worse" if the CI excludes 0, otherwise "not distinguishable"; no multiplicity correction.
18. **Fusion gain** = fused minus the best single-modality model, where the best single modality is chosen per seed on dev macro-F1 among {`bertweet_text_rule8`, the image head chosen in rule 15}; reported for macro-F1 and weighted F1 on dev and test, on the whole test set and on the agreed / disagreed subsets (rows where the normalised `label_text` equals / differs from `label_image`). Subset results are descriptive (no bootstrap).
19. **Post-hoc additions** (BERTweet-matched vs DistilBERT text-only paired bootstrap using the re-inferred DistilBERT predictions; the balanced ComplementNB and majority rows) are labelled post-hoc and were defined after the first Day 4 Task 2 results.
