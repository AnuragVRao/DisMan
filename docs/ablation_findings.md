# Ablation findings

Facts and measured numbers only. Source rows: `results/ablation/{A,B,C}/*.json` (one JSON per run); aggregates: `results/ablation/summary.csv`;
LaTeX: `results/ablation/tables.tex`; figure: `results/ablation/ladder_t2.pdf`. Method for T2 numbers: mean over seeds {42, 43, 44}, "±" is the sample std (ddof = 1), `n` = runs.
Paired differences use the same seed on both sides. With n = 3, treat differences smaller than roughly 0.01 macro-F1 as not established.
Every number in this document that comes from the result JSONs (and the attention probes in §4b and the embedding statistics in §1) is regenerated by `ablation/verify_findings.py` (run with `--write-log`; the per-check log is `results/ablation/findings_check.txt`). The C1 re-run comparison in §6 is a one-off before/after check, not part of that script. Run order and settings are in `ABLATION_PLAN.md`, `docs/v1_config.md`, `ablation/run_batch.py` (33 T2 runs, none failed, no result fell below the majority-class baseline of 0.0801 macro-F1).

## 1. Things found in the code that the plan did not anticipate

1. **v1 applied `RandomResizedCrop` (scale 0.9-1.0) to dev and test images too.** `capstone-final.ipynb` cell 15 keeps open_clip's *train* transform and cell 18 uses it for all three splits,
   so v1's logged dev/test T2 scores are measured on randomly cropped images. CLIP features therefore cannot be cached for L0-L2 (they run CLIP online); v2's cached features removed the augmentation as a side effect.
2. **v2's Task 2 text encoder is trained from random initialisation, not from pretrained DistilBERT.** `crisis_common.DualStreamClassifier` builds `DistilBertModel(bert_config)` whenever a config is passed, and v2's training cell passes one.
   Evidence: saved word-embedding std 0.0200 (random-init value; pretrained 0.0470); cosine similarity of the saved word embeddings with pretrained DistilBERT = -0.0002 (uncorrelated);
   cosine with the model's own seed-42 random init = 1.000 (relative distance 0.019, i.e. it barely moved at lr 1e-5). v1 used `from_pretrained`. Grep for models built from a config instead of `from_pretrained` (excluding `ablation/` and the old notebook): the only construction site is `crisis_common.py:265` (`DistilBertModel(bert_config)`), called from v2's training cell (`tools/build_notebook.py:247`) and from `demo/pipeline.py:36-38`, which builds the same module from the saved config and then loads *all* weights from the checkpoint, so for inference it is correct. CLIP and SBERT are always loaded with `from_pretrained`. Nothing was changed in v2.
3. **v2 iterates `tqdm(dl)` and `tqdm.auto` calls `iter(dl)` twice** (also with `disable=True`); the discarded iterator draws one seed from the loader's generator, so v2 trains on a shuffled order shifted by one draw per epoch.
   This is why a first re-implementation of v2's L4 gave test macro-F1 0.6022 instead of 0.5865 (same init, class weights, CUDA RNG state, data and eval-mode loss; different batch order). `ablation/t2_train.py` now emulates the draw and reproduces v2 exactly
   (first six step losses to 6 decimals; test acc 0.7975 / macro-F1 0.5865 / weighted-F1 0.7968). The shift is equivalent to a seed change, not a systematic effect, so it has no rung of its own. The 0.6022 vs 0.5865 gap is one measure of order-induced variation at this scale.
4. **v2 reproduces itself exactly** when its own notebook cells are re-run (`ablation/v2_t2_rerun.py`, outputs redirected): 0.7975 / 0.5865 / 0.7968, identical to the README and the saved history.
5. **T1 regression check passes.** v1's code, a fresh v2 retrain and the saved v2 artifact give identical predictions on all 2,237 test rows: accuracy 0.794367, weighted-F1 0.796959 (`ablation/t1_regression.py`).
6. The v1 T3 CLIP was verified, not assumed: HF `openai/clip-vit-base-patch32` (QuickGELU) reproduces the v1 demo cell's top-5 scores `[1, .474, .454, .45, .449]` on exactly one index row (next best misses by 12x more).

## 4b. How image information reaches the classifier (`DualStreamClassifier.forward`) and what `no_t2i` removes

```python
img = self.img_proj(img_vec).unsqueeze(1)                                  # [B, 1, 256]  the single CLIP vector
txt = self.txt_proj(self.text_encoder(...).last_hidden_state)              # [B, T, 256]  one vector per token
img_att = self.img_to_txt(img, txt, attn_mask == 0).squeeze(1)             # query = image, keys/values = text tokens
txt_att = self.txt_to_img(txt[:, 0:1, :], img).squeeze(1)                  # query = text [CLS], key/value = the single image
return self.classifier(torch.cat([img_att, txt_att], dim=-1))              # 512 -> 256 -> classes
```

`CrossModalAttention.forward` returns `LayerNorm(query + Dropout(MultiheadAttention(query, kv, kv)))`, i.e. **each block has a residual connection from its query**.

* **Full model.** `img_att = LN(img + Drop(MHA(q = image, k = v = text tokens)))`: the image reaches the classifier directly through the residual term, plus a text-attended update.
  `txt_att = LN(text_CLS + Drop(MHA(q = text_CLS, k = v = image)))`: the image is the *only* key, so the softmax weight is exactly 1.0 and the output does not depend on the text query.
  Verified numerically on `CrossModalAttention`: weights are 1.0, the attention output is identical for different text queries (max difference 0) and equals `out_proj(v_proj(image))` to 1e-5. So this block adds a **second, fixed linear copy of the image** to the text [CLS] vector, not text-conditioned attention.
  In training mode the attention-weight dropout (p = 0.2) acts on that single weight per head: each of the 4 heads' image contribution is zeroed with probability 0.208 (measured) and the others scaled by 1.25, i.e. head-wise dropout on this copy.
* **`no_t2i`** (`ablation/t2_models.py`) feeds the classifier `cat([img_att, txt_cls])` with `img_att` exactly as above and `txt_cls = txt_proj(...)[:, 0]` (no image content). **It therefore still has a direct image path, twice over:** the residual term inside `img_att`, which is concatenated straight into the MLP, and the image-to-text attention itself (the only query-dependent block) is kept.
  What it removes is only the second linear image copy added to the text [CLS] (the `txt_to_img` block, 263,680 parameters = the 67,352,840 → 67,089,160 difference) and that copy's head-wise dropout.
* `concat` feeds `cat([img_proj(CLIP), txt_cls])` with no attention at all; `image_only` feeds only `img_proj(CLIP)`.
* Reading for §4: the (suggestive, not established) -0.029 ± 0.024 for `no_t2i` is a loss of an extra linear image path and its regularisation, not of text-conditioned cross-modal attention, which `txt_to_img` never provided because of the single key.

## 8. Limitations

* n = 3 seeds per T2 configuration; T1/T3 are single deterministic runs (T3 differences of a few points on 529 rows are within noise). L0-L2 reproduce v1's configuration, not its exact numbers (library versions, CUDA non-determinism and random crops differ).
* The Kaggle open_clip version is unrecorded; the v1 train transform is taken from open_clip 3.3.0 (the RandomResizedCrop(0.9-1.0) default has been the same since 2.x).
* The Part B "full model" is L4a (pretrained encoder), not v2's L4, so Part B numbers do not directly compare with v2's headline.
* Reported tables use the IEEEtran conventions (booktabs, caption above); no IEEE report template existed in the repo to copy.

**Imbalance handling that existed before this study, and what had not been shown.** Task 1: logistic regression with `class_weight="balanced"`. Task 2: cross-entropy with inverse-frequency class weights rescaled to mean 1. Task 3: a balanced logistic probe and, in the voting ablation, class-balanced voting. Macro-F1 is the headline because it does not reward predicting the majority class. None of these treatments had been compared against not using it, or against alternatives.

**Conventions.** Macro-F1 is always computed over the fixed set of all 8 classes with `zero_division=0`. "Missing or found people" (9 train / 2 dev / 3 test rows) has F1 = 0 in every arm on both backbones (the model predicts it 33 times on B/32 and 20 times on L/14 over all arms and seeds, always wrongly), so no loss-level treatment fixes it: macro-F1 is capped at 7/8 = 0.875, and the macro-F1 over the other seven classes is the macro-F1 times 8/7. **Seed std** is the sample std (ddof 1) over seeds 42, 43, 44. The **test-sampling 95% CI** is a percentile bootstrap over the test rows (10,000 resamples; the same resampled rows for every arm and seed; the CI is for the seed-averaged quantity) and is a different quantity from the seed std; it is for reporting only and is never used to select. Selection uses dev only. "Better" and "worse" are used only where the paired 95% CI excludes 0 by more than 0.002; a bound within 0.002 of zero is called "borderline" (weak evidence), and otherwise the difference is "not distinguishable". The same rule applies to every comparison, including the recall of the small injured-or-dead class (8 dev and 10 test rows; per-run recall moves in steps of 0.125 on dev and 0.1 on test): a CI that excludes 0 is called "better" or "worse", and the word "not resolvable" is reserved for a CI that includes 0 on that class, where the data cannot separate a difference from no difference, which is not the same as no effect. Every recall comparison states its row count n. Pairwise comparisons were not corrected for multiple testing (about 10 arms on 2 backbones, several metrics), so isolated borderline exclusions should be read as weak evidence.

#### 9.10.1 Fine-tuned fusion against the frozen image-only head (pre-registered)

Pre-registered in the fine-tuned fusion addendum of `ablation/SELECTION_RULE.md` (committed before the three new runs). Arms: the frozen image-only L/14 head picked in 9.10 (lr 1e-4, dropout 0.2, d_model 128); pretrained DistilBERT fine-tuned in the v2 head (L4a-L14 `inv`); and pretrained all-MiniLM-L6-v2 fine-tuned in the same head (L4a-L14-MiniLM). **The DistilBERT arm reuses the existing L4a-L14 `inv` runs of 9.9, which were run before the pre-registration and whose numbers had been seen (disclosed in the pre-registration), so this is not a blind comparison; only the MiniLM arm (3 new runs) was run after it.**

Setup: CLIP L/14 768-d L2-normalised cached features, inverse-frequency loss, seeds 42, 43, 44, the L4a recipe (AMP, 10 epochs, batch 32, 3 warm-up epochs then cosine, text encoder at lr 1e-5 and every other module at 1e-4, v2's cross-attention head with d_model 256 and dropout 0.2), checkpoint = best dev macro-F1, test scored once. **The arms differ in more than the text:** trainable parameters (116,232 for the frozen head against 23,670,408 and 67,418,376), the head (d_model 128 image-only against the v2 cross-attention head at d_model 256) and the recipe (a fine-tuned encoder). The comparison does not isolate the text.

Validation: `FusionModel` built with DistilBERT has the same 124 state-dict tensors (names and shapes) as `DualStreamClassifier`, loads the stored L4a-L14 `inv` seed-42 checkpoint and reproduces its stored dev and test predictions on all 2,237 rows each; the three MiniLM checkpoints re-score to exactly the dev and test macro-F1 their training runs stored. Cost: the MiniLM runs took 310 to 366 s each inside the training script, about 17 minutes in total.

* In these two setups fine-tuned text fusion showed no detectable benefit over the frozen image-only head. This does not show that text is useless: the arms differ in more than the text (trainable parameters, head and recipe, see above), and the test is underpowered.
* Macro-F1 is not distinguishable from the frozen head for both fine-tuned models on dev (DistilBERT -0.0011 [-0.0177, +0.0153], MiniLM +0.0022 [-0.0162, +0.0202]) and on test (DistilBERT -0.0001 [-0.0224, +0.0228], MiniLM +0.0133 [-0.0085, +0.0381]).
* For DistilBERT, balanced accuracy (-0.0313 [-0.0505, -0.0150]) and vehicle recall (-0.1053 [-0.1930, -0.0185], n = 38) are worse than the frozen head on dev; on test vehicle recall is also worse (-0.0741 [-0.1481, -0.0101], n = 36), and the balanced-accuracy interval has an upper bound of +0.0009 (it touches zero; not distinguishable). These come from 16 uncorrected comparisons, so they are weak evidence in either direction.
* All four injured-or-dead recall comparisons (n = 8 dev, n = 10 test) have a CI that includes 0 and are "not resolvable" under the existing rule; none is evidence of an effect or of no effect.
* The MiniLM test columns in the table are reporting only. They are not selection results, and no claim here rests on them.
* The DistilBERT arm and the frozen head share the same test mean (0.6350) by coincidence: their predictions and their seed stds differ.
* Multiplicity: 9.10 has 38 arm slots (35 distinct trained configurations) and, separately, this subsection has 16 pairwise comparisons (2 arms x 4 metrics x 2 splits); neither set is corrected for multiplicity.
* Under the pre-registered rule the pick is the frozen image-only head: the simplest model within noise of the best under the pre-registered rule; fine-tuned text fusion showed no detectable benefit; the test is underpowered.
